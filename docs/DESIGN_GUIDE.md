# PLOT OS v2 디자인 가이드

작성일: 2026-11-12 · 적용 대상: `web-v2/` · Step 01

서울 상업용 빌딩 30–150억 원의 후보 탐색과 인수 검토를 위한 작업 화면이다. 400개 합성 건물과 25개 상세 임대차 예시를 바탕으로 한다. 이 문서의 치수와 색은 PLOT OS의 구현 기준이며 다른 서비스의 측정값이 아니다. ValueMap / Disco 등에서 연상되는 지도 중심 탐색, 높은 정보 밀도, 명료한 가격 위계만 영감으로 삼는다. 해당 서비스의 최신 화면은 조사하지 않았으며 로고, 에셋, 문구, 화면을 복제하지 않는다.

## 1. 제품 원칙과 이번 단계의 범위

- **지도 우선:** Deal Radar는 왼쪽 후보 목록, 가운데 지도, 오른쪽 선택 건물 상세 drawer로 구성한다. 필터는 상단 가로 바에 두어 지도를 좁히지 않는다.
- **숫자 우선:** 호가 → 대지 평당가 → Cap rate → 조건 적합도 순서로 읽힌다. 최대 매입가, 필요 자기자본, IRR은 가정과 계산 근거에 연결한다. 높은 점수를 투자 추천이나 확정 수익으로 표현하지 않는다.
- **밀도와 안정감:** 흰 표면, 회색 구분선, 작은 반경, 정렬된 숫자를 사용한다. 모든 영역을 큰 카드로 감싸거나 여백으로 화면을 채우지 않는다. 계산 화면의 본문은 최소 14px, 보조 지표와 표는 최소 12px를 목표로 한다.
- **차분한 금융 UI:** 주색은 teal 하나로 통일한다. 장식용 그라디언트, 이모지, 유리 효과·배경 blur, 기울어진 프리뷰, 과한 그림자, 불필요한 애니메이션을 사용하지 않는다.
- **정직한 데이터:** `예시 데이터 · 실제 매물 아님`을 모든 경로와 인쇄물에서 유지한다. 거대한 `DEMO` 배너나 마케팅 리본 대신 작은 고정 고지를 사용한다. 위치·사진이 실제 건물의 증거처럼 보이지 않도록 각각 예시임을 밝힌다.

JavaScript에서 공통 고지 상수를 만들 때 다음 값을 그대로 사용한다. HTML과 문서에는 동일한 한글을 UTF-8로 기록한다.

```js
const EXAMPLE_DATA_LABEL = '\uC608\uC2DC \uB370\uC774\uD130 \u00B7 \uC2E4\uC81C \uB9E4\uBB3C \uC544\uB2D8';
// 예시 데이터 · 실제 매물 아님
```

이번 단계는 문서와 토큰 준비다. 기존 `index.html`은 이미 `css/tokens.css`를 다른 화면 CSS보다 먼저 로드한다. 새 토큰은 이 파일의 `:root`에 추가한다. 기존 `--navy`, `--ink`, `--accent`, `--radius` 등은 호환용으로 유지하며 전면 재스타일링, 지도 교체, 사진 연결은 후속 단계에서 한다. 현재 12/7px 반경과 76px 내비게이션은 기존 화면 값이며 아래 목표 규격으로 이미 바뀌었다고 간주하지 않는다.

## 2. 레이아웃과 반응형 규격

### 공통 shell

상단 내비게이션은 56px, 고지 행은 최소 28px, 필터 바는 최소 48px다. 고지나 필터가 줄바꿈되면 실제 높이에 맞춰 workspace를 줄이며 고정 offset으로 내용을 가리지 않는다. 내비게이션은 브랜드, `딜 레이더`, `매물 탐색`, `제안서`, `근거 모드`로 구성한다. 영어 번역은 필요할 때만 보조 텍스트로 둔다. 현재 경로는 밑줄과 `aria-current="page"`로 함께 표시한다.

Radar는 전체 폭을 사용한다. 공통 shell을 세로 flex로 두고 workspace에 `flex: 1; min-height: 0`을 부여한다. 지원 브라우저에서 `100dvh`를 사용하고 `100vh`를 대체값으로 둔다. 목록·drawer는 독립 스크롤, 지도는 남은 높이를 채운다. 목록 헤더와 drawer 요약 헤더는 각 스크롤 영역의 `top: 0`에서 sticky다. 지도 위에 전역 KPI 네 장을 쌓지 않고 목록 헤더에 결과 수·정렬, 상세에 선택 건물 KPI를 둔다.

| viewport | 목록 | 지도 | 상세 drawer | 동작 |
|---|---:|---|---:|---|
| 1600–1920px | 400px | 남은 폭, 최소 480px | 440px | 선택 시 세 칼럼, 미선택 시 지도 확장 |
| 1440–1599px | 360px | 남은 폭, 최소 480px | 400px | 세 칼럼, 칼럼 사이 1px hairline |
| 1280–1439px | 360px | 남은 폭 | 400px overlay | 선택 시 지도 오른쪽에 overlay; 목록 유지 |
| 1024–1279px | 320px | 남은 폭 | 400px overlay | 태블릿 가로, 필터 일부는 `상세 조건` popover |
| 768–1023px | 목록/지도 전환 | 활성 모드가 전체 폭 | 최대 480px modal | 필터는 접기, 상세는 우측 sheet |
| 767px 이하 | 단일 칼럼 | 명시적 지도 전환 | 전체 화면 sheet | 표 영역만 가로 스크롤; 터치 조작 44px |

위 구간은 CSS media query로 선언한다. CSS custom property는 media query 조건에서 사용하지 않는다. 기존 화면의 1200/1600px 분기는 Step 04에 위 기준으로 정리한다. 1920px 초과에서도 Radar 지도는 확장하고, 계산·근거 페이지의 본문은 `--page-max-width` 이내에서 중앙 정렬한다.

1280px에서는 360 + 480 + 400px을 동시에 확보할 수 없으므로 drawer를 overlay로 전환한다. overlay 아래 선택 마커가 숨지 않게 지도 padding을 조정하고 패널 크기·열림 상태가 바뀌면 지도 resize를 호출한다. drawer 닫기 후 목록 스크롤과 필터를 복원한다. 데스크톱 비모달 drawer에는 focus trap을 두지 않는다. 좁은 화면의 modal sheet만 focus trap, Escape 닫기, 배경 비활성화, 열었던 요소로 focus 복귀를 적용한다.

계산 화면은 바깥 여백 24px, 12칼럼 개념 grid, 간격 16px로 구성한다. 1440px 이상에서 입력 4/결과 8 비율, 1024–1439px에서 5/7 비율, 그 아래는 입력→결과 순으로 쌓는다. 근거는 숫자 옆 버튼으로 열고 필드명·단위·수식·입력·출처·신뢰도를 연결한다.

## 3. 토큰 계약

구현 원본은 [`web-v2/css/tokens.css`](../web-v2/css/tokens.css)다. 새 컴포넌트는 의미 기반 토큰을 사용한다. 기존 별칭의 교체는 Step 04에 컴포넌트별로 진행한다. 고지, 경고, 근거 출처는 대비가 낮은 장식색을 사용하지 않는다.

| 역할 | 토큰 | 값 / 사용 |
|---|---|---|
| 바탕 / 표면 / 보조 표면 | `--color-canvas`, `--color-surface`, `--color-surface-subtle` | `#f3f5f7` / `#ffffff` / `#f8fafb` |
| hover 표면 | `--color-surface-hover` | `#edf2f5` |
| 본문 / 보조 / 반전 | `--color-text`, `--color-text-muted`, `--color-text-inverse` | `#17283b` / `#586779` / `#ffffff` |
| 선 / 조작 경계 | `--color-border`, `--color-border-strong` | `#e0e6ec` / `#7c8b9b`; 옅은 선은 구획용 |
| 내비게이션 | `--color-nav` | `#111e30` |
| 주색 / hover / 선택 바탕 | `--color-primary`, `--color-primary-hover`, `--color-primary-subtle` | `#087e75` / `#05665f` / `#e7f4f1` |
| 어두운 표면 강조 | `--color-primary-on-dark` | `#83dbca`; 흰 바탕의 작은 글자에는 사용하지 않음 |
| 상승 / 하락 | `--color-up`, `--color-down` | `#16734a` / `#b23b3b` |
| 경고 / 정보 | `--color-warning`, `--color-info` | `#855500` / `#285ea8` |
| 의미색 옅은 바탕 | 위 의미색의 `-subtle` 토큰 | 텍스트는 해당 진한 의미색으로 표시 |
| focus | `--color-focus`, `--focus-width`, `--focus-offset` | `#285ea8`, 3px, 2px |

상승/하락은 방향이며 유불리를 자동 단정하지 않는다. 임대료 상승과 비용 상승은 해석이 다르다. `+0.3%p`, `비용 증가` 같은 부호·문구를 함께 쓴다. 중요한 오류는 `--color-down`과 원인 텍스트로, 낮은 신뢰도 가정은 `--color-warning`과 `가정` 표시로 구분한다.

### 타이포그래피와 폰트

`--font-sans`: `Pretendard, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`. 금융 숫자도 같은 글꼴을 사용하고 `font-variant-numeric: var(--numeric-variant)` (`tabular-nums lining-nums`)를 적용한다. monospace는 식별자·수식에만 사용한다. 호가의 단위를 작은 보조 글자로 두되 숫자와 떨어뜨리지 않는다.

| 토큰 | 크기 | 용도 |
|---|---:|---|
| `--font-size-caption` | 12px | 보조 설명·고지·표 셀 |
| `--font-size-body` | 14px | 본문·입력·목록 제목 |
| `--font-size-emphasis` | 16px | 강조 행 |
| `--font-size-section` | 18px | 섹션 제목 |
| `--font-size-title` | 24px | 페이지 제목 |
| `--font-size-price` | 24px | 호가·최대 매입가 |
| `--font-size-kpi` | 28px | 대표 KPI |

굵기는 regular 400 / medium 500 / semibold 600 / bold 700. 줄높이는 숫자·짧은 제목 1.3, UI 본문 1.5, 설명문 1.7이다. 긴 한글 제목은 `word-break: keep-all; overflow-wrap: anywhere`로 처리하고, 가정·오류 메시지를 말줄임으로 숨기지 않는다. 가격에 과한 음수 자간을 적용하지 않는다.

Step 04에서 `index.html`의 로컬 CSS 앞에 아래 버전 고정 CDN stylesheet를 추가한다. 폰트는 이번 단계에서 다운로드하거나 연결하지 않는다. 현재 shell 테스트의 외부 URL 금지 조건도 그 시점에 이 stylesheet만 허용하도록 갱신한다. 폰트 실패 시 위 시스템 글꼴로 즉시 화면을 사용할 수 있어야 하며 앱 초기화를 폰트 로드에 종속시키지 않는다.

```html
<link rel="stylesheet" crossorigin="anonymous"
  href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard-dynamic-subset.min.css">
```

URL과 `Pretendard` family 이름은 [Pretendard 공식 웹폰트 안내](https://github.com/orioncactus/pretendard#웹폰트)에서 확인했다(2026-11-12). 앱 브라우저에서 실제 font 요청 성공 여부는 UNKNOWN이다.

### 간격·테두리·레이어

- 간격: `--space-0/half/1/2/3/4/5/6/8/10/12` = 0/2/4/8/12/16/20/24/32/40/48px. 칩 내부 4–8px, 카드 내부 12–16px, 섹션 간 24px를 기본으로 한다.
- 반경: `--radius-badge: 2px`, `--radius-control: 4px`, `--radius-panel: 6px`. 둥근 pill은 마커·클러스터 등 위치 정보의 모양에만 제한적으로 사용한다.
- 테두리: `--border-width: 1px`. 카드·표는 hairline으로 구획한다. 입력과 버튼 경계는 `--color-border-strong`을 쓴다.
- 그림자: `--shadow-panel`은 미세한 표면 구분, `--shadow-popover`는 뜬 필터·popup, `--shadow-drawer`는 상세 overlay에만 사용한다. 목록의 모든 카드에 진한 그림자를 주지 않는다.
- 조작 높이: `--control-height: 36px`, 터치 환경은 `--control-height-touch: 44px`. 모션은 `--motion-duration: 160ms`, `--motion-easing: ease`; reduced-motion을 존중한다.
- z-index: map control 10 → sticky 20 → nav 30 → drawer 40 → popover 50 → modal 60 → toast 70. MapLibre 내부 레이어는 지도 컨테이너의 stacking context에 가둔다. modal은 항상 drawer보다 위다.
- 레이아웃 토큰은 `--nav-height`, `--disclosure-height`, `--filterbar-height`, `--listing-width[-wide]`, `--drawer-width[-wide]`, `--map-min-width`, `--page-max-width`를 사용한다.

## 4. 컴포넌트별 구현 기준

### 매물 목록 카드

카드 패딩 12px, 썸네일 96×72px(4:3, `object-fit: cover`), 본문과 간격 12px. 고정 높이로 텍스트를 자르지 않으며 대략 156–180px 안에서 비교할 지표를 모은다. 첫 줄에는 구·동과 용도, 다음은 호가 `85.4억`, 이어 `대지 4,820만원/평`, `Cap rate 3.2%`, `적합도 82점`을 표시한다. 건물명은 14px semibold, 호가 24px semibold, 보조 지표 12px다. 월세·연면적·역 도보 등 부가 정보는 최대 한 행으로 정리한다.

썸네일에는 `예시 사진`을 붙이고 상세에서는 `해당 건물의 실제 사진 아님`을 밝힌다. 이미지 alt는 예시 외관의 보이는 특징만 설명한다. 파일명이나 합성 주소를 실제 촬영 위치로 쓰지 않는다. `loading="lazy"`, 명시적 width/height, 이미지 실패 시 동일 크기 중립 placeholder를 사용한다. 출처·사용 조건·예시 고지를 manifest에 남기고 라이선스를 확인하지 못한 이미지는 사용하지 않는다. 바이너리 파일은 커밋하지 않고 text manifest·생성 스크립트를 남긴다.

hover는 배경·경계 변화, selected는 주색 경계와 `선택됨` 텍스트로 표시한다. 마커 hover와 카드 hover를 동기화하되 hover만으로 상세를 열지 않는다. 건물명은 실제 링크, 별도 액션은 별도 버튼으로 만들고 링크 안에 버튼을 중첩하지 않는다.

### 필터 바와 칩

검색, 지역, 매매가, 용도, 도보, 자기자본·LTV·목표 IRR을 가로 배치한다. 전체 조건은 `상세 조건`에서 접근 가능하게 하고 적용된 조건만 요약 칩으로 표시한다. 필터 헤더에 `조건 일치 N개`와 초기화를 둔다. 단위와 최소·최대 범위를 입력 옆에 표시한다. 칩은 `aria-pressed`, 제거 버튼은 `강남구 조건 해제`처럼 이름을 준다. 자동 계산 중에는 이전 결과를 유지하고 작은 `계산 중` 상태로 표시해 카드 영역의 점프를 막는다.

### KPI / 최대 매입가 / Value-up

KPI는 label→값→단위→기준 시점·가정 순이다. 네 개 이하를 같은 폭으로 놓고 1024px 미만에서는 두 칼럼으로 줄인다. 대표 결과 하나만 강조하고 모두 어두운 카드로 칠하지 않는다. 최대 매입가는 항상 `호가`, `최대 매입가`, `차이`를 함께 보여준다. 상한은 기존 `bidAmount()`의 0.1억 단위 내림 규칙을 보존한다. Value-up은 기준/개선 후 값을 같은 단위로 비교하고 공사비·기간·공실 가정을 가까이 둔다. 근거 숫자는 dotted underline과 키보드로 접근 가능한 버튼을 유지한다.

### 임대차 / 비교사례 표

행 높이 40–44px, 셀 좌우 패딩 12px, 폰트 12–13px. header는 보조 표면, 행은 흰 바탕과 아래 1px hairline으로 구분한다. zebra 줄무늬는 쓰지 않는다. 텍스트는 왼쪽, 수치와 단위는 오른쪽 정렬하고 합계 행은 굵기와 윗선으로 구분한다. 단위는 header에 `월세(만원/월)`처럼 표시한다. `caption`, `th scope`, 정렬 버튼의 `aria-sort`를 제공한다. 표 header는 표 스크롤 안에서 sticky, 좁은 화면은 표 컨테이너만 가로 스크롤한다. 비교사례에도 합성 데이터 고지를 유지한다.

### 슬라이더 / 탭 / badge

- 슬라이더는 native range, label, 현재값 output, 직접 숫자 입력을 함께 둔다. 키보드 증감과 min/max/step을 같은 값으로 설정한다. LTV는 0.65 저장값을 65%로 표시한다. 로컬 계산의 기존 debounce를 보존하며 재렌더링으로 focus를 잃지 않는다.
- 탭은 36px 이상 높이, 2px 활성 밑줄과 굵기로 구분한다. 같은 화면 panel 전환은 `tablist/tab/tabpanel` 및 방향키를, 별도 URL 이동은 링크와 `aria-current`를 사용한다. 두 패턴을 혼합하지 않는다.
- badge는 12px, 2px 반경, 짧은 텍스트를 사용한다. `상세 임대차`, `요약`, `가정`, `산출 불가`, `조건 외`처럼 의미를 명확히 한다. 예시 데이터 고지와 투자 상태를 같은 의미색으로 혼동시키지 않는다.

### 지도 마커 / 클러스터 / popup

Step 03의 지도는 MapLibre GL JS + OpenFreeMap으로 구현한다. 버전 고정 JS/CSS를 public CDN의 `<script>`/`<link>`로 로드하며 npm·빌드 도구·API key를 추가하지 않는다. basemap은 `https://tiles.openfreemap.org/styles/liberty`를 기본 후보로 두고 읽기 어려우면 positron/bright를 검토한다. `tile.openstreetmap.org`, Kakao, Naver는 사용하지 않는다. 지도 스타일과 한국어 label 지원의 실제 결과는 구현 시 확인하며 지원 여부를 단정하지 않는다.

점수 구간은 이번 가이드의 표시 기준이며 엔진 수식을 바꾸지 않는다. 카드와 마커에 같은 `row.score`를 사용한다.

| 점수 / 상태 | 토큰 | 표현 |
|---|---|---|
| 80–100 | `--map-score-high` | teal + 숫자 |
| 60–79 | `--map-score-mid` | blue + 숫자 |
| 0–59 | `--map-score-low` | slate + 숫자 |
| 산출 불가 | `--map-score-unknown` | 중립 보라회색 + `—`, 설명은 `산출 불가` |
| 조건 외 | `--map-context` | 작은 빈 원/약한 경계, 일반 후보와 구분 |
| cluster | `--map-cluster` | 흰 글자로 조건 일치 건물 수 |
| 선택됨 | `--map-selected` | 기존 색 위에 이중 outline과 크기 변화 |

일반 마커 높이는 28–32px, cluster는 개수에 따라 32/40/48px의 세 크기로 제한한다. 마커 숫자는 흰색 12px semibold다. 색뿐 아니라 점수와 범례를 보여준다. 선택 경계에는 흰 halo와 어두운 외곽선을 함께 적용해 다양한 바탕에서 구분되게 한다. 지도 안의 실제 조작 hit 영역은 최소 24px, 터치 시 44px 목표다.

조건 일치 포인트만 clustering하며 조건 외 포인트는 별도 context layer로 표시한다. cluster 수와 목록 결과 수의 집합이 같아야 한다. cluster 클릭은 확대, 단일 마커 선택은 목록 선택·drawer와 동기화한다. popup은 폭 240–280px, 예시 썸네일, 호가·평당가·점수, `상세 보기` 링크, 닫기로 제한한다. 좌표는 `[lng, lat]` 순서다. 합성 좌표는 필지와 일치한다고 주장하지 않고 `예시 위치`를 상시 표시한다.

OpenFreeMap과 OpenStreetMap contributors의 attribution을 지도 하단에 링크로 항상 보이게 둔다. drawer, popup, 고지가 가리지 않게 여백을 확보하며 지도 출처를 건물 데이터 출처처럼 표현하지 않는다. WebGL canvas와 별개로 모든 후보를 HTML 목록과 링크로 열 수 있어야 한다.

### 빈 화면 / 오류 / 외부 리소스 실패

| 상황 | 안내와 동작 |
|---|---|
| 조건 일치 0개 | `조건에 맞는 예시 건물이 없습니다` + 조건 요약 + `조건 초기화`; 기존 필터 유지 |
| 상세 임대차 없음 | `상세 임대차 자료 없음` + 요약 지표 유지; 빈 표를 실자료처럼 만들지 않음 |
| IRR 등 산출 불가 | `산출 불가` + 계산 실패 원인·근거 연결; 0%로 대체하지 않음 |
| CDN / WebGL 초기화 실패 | 지도 영역에 `지도를 불러오지 못했습니다. 목록에서 건물을 확인해 주세요.` + 재시도; 목록·필터 정상 동작 |
| 타일·스타일 실패 / 장시간 미표시 | 지도 내부 로딩 상태를 종료하고 오류 표시·재시도; 부분 실패라면 `일부 지도 정보가 표시되지 않습니다`와 마지막 화면 유지 |
| 사진 실패 | 같은 크기 placeholder + `예시 사진 없음`; broken-image 아이콘과 반복 자동 재요청 방지 |
| 데이터 요청 실패 | 실패한 영역에 원인과 `다시 시도`; 전체 결과가 빈 것처럼 보이지 않음 |

지도 어댑터의 `element/update/highlight/destroy/onOpen/onHover` 계약과 compact preview를 보존한다. DOM 연결 전 초기화, 초기 로드 전 filter update, 반복 경로 전환 시 listener·WebGL 정리를 별도로 검증한다. 지도 실패가 `loadCore()`나 목록 초기화를 막지 않게 분리한다. 재시도에 의한 중복 map 인스턴스를 만들지 않는다. 외부 리소스의 성공 여부는 현재 UNKNOWN이며 오류 처리의 완성 여부와 구별한다.

## 5. 한국어 숫자와 단위 표기

원천 값은 KRW·m²·ratio 그대로 유지하고 표시 단계에서만 변환한다. `js/ui/format.js`를 공통 경로로 사용한다. 다음 표는 표시 계약이며 기존 계산식을 변경하는 지시가 아니다.

| 항목 | 규칙 | 예시 |
|---|---|---|
| 매매가·가치·자기자본 | 1억 = 100,000,000원, 소수 최대 1자리 | 8,540,000,000원 → `85.4억` |
| 최대 매입가 | 일반 반올림 금지, 0.1억 단위 내림 | 8,549,000,000원 → `85.4억` |
| 월세·보증금·운영비 | 만원 단위, 천 단위 쉼표, 기본 정수 반올림 | 12,340,000원 → `1,234만원/월` |
| 평당가 | 반드시 분모 구분; 기본 정수 만원 | `대지 4,820만원/평`, `연면적 2,160만원/평` |
| 면적 | 평 = m² × 121/400, 표시 소수 최대 1자리 | `330.6m² (100평)` |
| Cap rate / IRR / 공실률 | ratio × 100, 소수 최대 1자리 | 0.032 → `3.2%` |
| 두 비율의 차이 | 퍼센트포인트, 양수는 + | 3.2% → 3.5%: `+0.3%p` |
| LTV | % 정수 기본, 조작 step과 일치 | `65%` |
| 적합도 / 개수 / 도보 | 정수, 단위 고정 | `82점`, `24개`, `도보 7분` |
| 기준일 | YYYY.MM.DD, 출처에 있는 날짜만 | 날짜 미확인: `기준일 UNKNOWN` |

대지·연면적·전용면적을 혼용하지 않는다. 임대료 평당가는 전용면적 기준임을 표시하며 전용면적을 모르면 UNKNOWN이다. 월·연 단위를 제목 또는 셀에 남긴다. 계약 단위가 섞인 범위는 `30–150억`, `800–1,200만원/월`처럼 단위를 끝에 쓰되 의미가 명확해야 한다. 기본 0은 실제 숫자일 때만 표시하고 누락·NaN·Infinity는 `—`와 설명 `자료 없음` 또는 `산출 불가`를 붙인다. 원천 미확인 값은 `UNKNOWN`을 유지한다. 아주 작은 양수를 반올림해 0으로 오인할 수 있으면 원값을 근거에 제공하고 `<0.1%` 등 정밀도 안내를 별도로 구현·검증한다.

목록, drawer, popup, 제안서에서 동일한 포맷터와 분모를 사용한다. 표시 반올림 값으로 재계산하지 않는다. Cap rate는 연 NOI/호가 등 실제 계산 분모를 근거에서 명시하고 확인되지 않은 `수익 보장` 같은 문구를 사용하지 않는다.

## 6. 접근성 기준

본문·보조 텍스트의 대비 목표는 4.5:1 이상, 큰 텍스트와 필수 UI 경계는 3:1 이상으로 둔다. 실제 사용한 전경/배경 조합을 검증한다. 연한 hairline은 장식적 구획으로만 사용하며 입력 경계나 선택 상태의 유일한 표시는 될 수 없다. 어두운 header에서는 흰색 또는 `--color-primary-on-dark`를 사용한다.

모든 조작에 `:focus-visible` 3px ring과 2px offset을 적용한다. 어두운 배경·사진 위에서는 흰 분리선도 추가하고 overflow에 잘리지 않게 한다. 링크·버튼에 명시적인 이름을 주고, tooltip만으로 단위·가정을 설명하지 않는다. skip link, 한국어 `lang`, 제목 순서, range label, 결과 개수의 `aria-live="polite"`, 로딩 영역의 `aria-busy`를 유지한다. 지도 이동이 키보드를 가두지 않게 하고 같은 작업을 목록에서도 수행 가능하게 한다. 확대 200%, reduced-motion, 키보드만 사용하기, 태블릿 터치를 확인한다.

## 7. 인쇄와 Buyer / Seller 제안서

화면에서 Buyer/Seller 대상과 선택 건물·가정을 명시한다. 가격 범위, 비교사례, 주요 가정, 근거, 기준일을 같은 순서로 제시한다. 버튼보다 제안 내용이 우선이다. 확정 거래나 검증된 감정평가처럼 보이는 제목은 쓰지 않는다.

기존 `proposal.css`와 `print.css`를 유지하며 A4 세로·여백 12mm를 후속 목표로 검증한다. 인쇄에서는 내비게이션·필터·조작·sticky·그림자를 제거하고 흰 배경/진한 글자를 사용한다. 표 header 반복, 짧은 KPI/카드의 `break-inside: avoid`, 긴 표의 자연스러운 페이지 분할을 허용한다. 지도 WebGL 출력에 의존하지 말고 예시 위치 텍스트 또는 검증한 인쇄 대체 요소를 사용한다. 고지 `예시 데이터 · 실제 매물 아님`, 사진의 예시 표시·출처, 가정·UNKNOWN은 인쇄에서도 숨기지 않는다. 지도를 출력한다면 attribution도 함께 남긴다. 실제 A4 출력 결과는 UNKNOWN이며 최종 브라우저 검증이 필요하다.

## 8. Do / Don't

| Do | Don't |
|---|---|
| 숫자와 단위의 기준선을 맞춘다 | 단위 없는 큰 수치나 제각각의 반올림 |
| 지도·목록·상세의 선택과 결과 집합을 연결한다 | hover로 drawer를 강제로 열거나 필터마다 지도를 초기화 |
| 고지와 출처를 작지만 읽을 수 있게 유지한다 | 대형 DEMO 리본 또는 고지를 숨긴 실매물 같은 화면 |
| 가격·평당가·Cap rate·적합도를 우선한다 | 수식어, 과도한 영어 eyebrow, 장식 KPI로 공간 낭비 |
| 사진과 위치에 예시 고지를 붙인다 | 실제 촬영·주소·검증된 매물이라는 인상 |
| 1px 선, 작은 반경, 제한된 강조색을 사용한다 | toy gradient, emoji, glassmorphism, 과한 shadow |
| 실측·가정·계산·UNKNOWN을 구분한다 | 누락을 0으로 채우거나 점수를 투자 등급으로 포장 |
| 네트워크 실패 시 목록으로 탐색을 계속한다 | 빈 지도나 무한 로딩으로 전체 앱을 막음 |

## 9. 적용 순서와 완료 확인

1. **Step 01:** 이 문서와 토큰 정의를 추가하고 기존 CSS import·고지·테스트를 보존한다. 실제 UI 전환 여부를 문서와 구분한다.
2. **Step 02:** 예시 사진 manifest·결정적 배정·카드 공통 이미지 컴포넌트와 이미지 실패 처리를 연결한다. 금융 데이터 생성 순서를 바꾸지 않는다.
3. **Step 03:** 지도 어댑터를 교체하고 클러스터·조건 외 포인트·선택 동기화·attribution·CDN/타일 실패를 검증한다.
4. **Step 04:** shell→Radar 목록/지도/drawer→계산/Value-up→Evidence→제안서 순으로 새 토큰을 적용하고 Pretendard CDN을 연결한다. 기존 클래스와 CSS hardcoded 값을 점진적으로 정리한다.
5. **Step 05:** 1920/1440/1280/1024/768px, 200% 확대, keyboard, 사진/CDN/타일 실패, 반복 경로 전환, A4를 브라우저에서 확인한다. `node --test --test-isolation=none`에 `tests/*.test.mjs` 파일을 명시적으로 나열해 전체 테스트를 실행한다.

현재 미확인 항목: 브라우저 폰트/CDN/타일 접근, WebGL, 실제 색 조합의 화면 대비, 한국어 지도 label, 사진 라이선스와 적합한 풀, 실제 좌표의 행정구역·필지 대응, A4 출력. 모두 UNKNOWN이며 디자인 문서만으로 검증 완료라 하지 않는다. 실매물·현재 시세·확정 수익을 새로 주장하지 않는다.
